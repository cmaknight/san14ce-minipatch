# 그룹 8. 훈련비 비례 차감 (`traincost` / ini `train_cost` / 소스 `src/dll/feat_train.c`)

대상은 SAN14CE_KO.exe 1.0.1(PE 타임스탬프 0x6A983C25)이고, 주소는 모두 RVA다. 전체 구조와 공통 게임 구조는 [00-overview.md](00-overview.md)에 있다.

## 하는 일
- 원본: 훈련 담당이 있는 도시는 매 순 훈련비(300 − 할인)를 낸다. 도시나 관할 관문 중 하나라도 사기가 1 이상 오르면 전액이다. 월초 모병으로 사기가 2~3 떨어져도 300이 나간다.
- 바뀜: 훈련비 = 원래 비용 × 실제 상승 합 ÷ 계산 상승 합(올림). 예: 계산 12, 실제 3 → 75. 계산 상승을 다 쓰면 원래 비용과 같다.
- 금이 비례 비용 이상이면 훈련한다. 수지 예상의 훈련비도 비례 값이다. 플레이어·AI 도시 모두 적용. 진행 중인 세이브에 즉시 적용된다.
- 바뀌지 않는 것: 사기 상승량, 담당 경험치·공적, 모병, 훈련 담당 임명 화면의 비용 표시(순당 최대 비용).

## 구현 방식
- 훈련 0x300E50은 비용 `0x266850(도시, 담당)`을 한 번 구해 금 검사(0x300ED1)·차감(0x3010EE)·지출 누계(0x3010F9)에 그대로 쓴다. 그래서 비용 호출만 감싸 비례 값을 돌려주면 세 곳이 함께 바뀐다.
- 비용은 훈련을 적용하기 전에 구하므로, 대상마다 상승을 미리 계산한다(적용은 하지 않는다).
  - 대상: 도시 자신 + 관할 관문. 관문은 ROOT+0xA0 목록을 게임 공용 노드 풀로 직접 따라가며 `0x22A7B0(관문) == 도시`인 것만(0x22CFD0과 같은 순회, 읽기만).
  - 대상마다: 사기(+0x44 byte) ≥ 최대사기(`0x22EA10`)이거나 병사(+0x3C int)가 0이면 건너뛴다. 계산 상승 g = `0x268F70(대상, 담당)`, g ≤ 0이면 건너뛴다.
  - 계산 합 += g. 실제 합 += min(g, 최대사기 − 사기). 이민족(세력 종류 46~50)은 사기가 오르지 않으므로 실제 0으로 센다.
- 결과: 계산 합이 0이면 0. 아니면 `(base × act + calc − 1) / calc`(int64, 올림).
- 그대로 돌려주는 경우: 도시·담당이 없음, 담당 무효(`0x32F500`), 도시 훈련 담당(+0xCC)이 0, 훅 안 예외(SEH).

## 새 버전에서 다시 맞추는 순서
1. 새 실행 파일을 디스어셈블해 상수 300(`[0x1A4846C]`)을 읽는 비용 함수(0x266850 대응)를 찾고 호출처를 모두 모은다.
2. 턴 처리(0x302FA0 대응, 거점마다 모병 → 개발 → 훈련) 안의 훈련 함수를 찾고, 그 안 첫 비용 호출(0x300EBA)이 금 검사·`0x273B0` 차감·`0x223A00` 누계로 이어지는지 확인한다.
3. 상승량 함수(0x268EA0 대응) 안의 비용 호출(0x268F10)과, 수지 예상(0x2DC440 대응)에서 시험 훈련 뒤 비용 호출(0x2DC763)을 찾는다. UI 호출(0x780AE7)은 제외한다.
4. 상승식(0x268F70)·최대사기(0x22EA10)·관할 도시(0x22A7B0)·적용(0x2238F0)의 자르기·이민족 조건을 확인한다.
5. 관문 목록(ROOT+0xA0)과 노드 풀 전역(0x27D10E8/F0/1120)을 0x22CFD0 대응 함수의 순회에서 다시 읽는다.
6. `feat_train.c` enum 전부와 필드(+0x44, +0x3C, +0xCC, vfunc +0xB0/+0x60, ROOT+0xDF30)를 갱신한다.

## 검증
- 게임에서 확인: 1일 모병 직후 사기가 조금 오를 때 금 차감이 비례 값.
- 미확인: 사기가 크게 떨어졌을 때 300 그대로인지, 지출 누계(+0x50)와 수지 예상 표시, 금이 300 미만이어도 비례 비용 이상이면 훈련되는지, AI 도시 동작.
- 알려진 문제(미해결): 담당 없음 → 훈련 담당 임명 직후 도시 정보를 처음 열면 금 지출이 0으로 보이고, 닫았다 다시 열면 정상인 경우가 있다(재현 불안정).
  - 비례식은 이 상태에서 0이 될 수 없다. 수지 예상 캐시(0x2781180, 도시당 0x18 B) +0x14는 매번 다시 계산한다.
  - 추정: 화면이 값을 가져가는 순간 임명이 도시 +0xCC에 아직 반영되지 않아 시험 훈련이 실패했다. 원본에서도 같은지는 미확인.

## 함정·결정
- 비용 호출 3곳을 감싸 미리 계산한다. 적용 호출(0x300EFC·0x3010C4 `0x2238F0`)을 감싸 전후 사기로 실제 상승을 세는 방식은 쓰지 않는다. 금 검사 0x300ED1이 적용보다 먼저라 "비례 비용만 있으면 훈련"을 할 수 없고, 시험 모드인 예상 지출은 적용이 없어 따로 계산해야 하기 때문이다.
- 사기 1당 단가가 아니라 비례식을 쓴다. 단가 방식은 담당 능력에 따라 같은 사기에 내는 금이 달라지는 원본 성격을 바꾼다.
- 계산 상승이 0이면 0을 낸다. 원본은 이때 훈련하지 않으면서 예상 지출에만 전액을 넣었다.
- 관문이 대상이다(도시만이 아님). 출진 부대는 대상이 아니다.
- 이민족: 계산 상승에는 넣고 실제 상승은 0. 이민족 도시만 있으면 비용이 0이 된다.
- 0x268F10에서 첫 인자가 관문인지 도시인지는 확인하지 않았다. 훅은 첫 인자 +0xCC(훈련 담당)가 0이면 원래 비용을 돌려준다.

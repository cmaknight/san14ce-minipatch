# 그룹 3. 페이즈 종료시 자동 탐색 (`autosearch` / ini `auto_search` / 소스 `src/dll/feat_autosearch.c`, `src/dll/feat_autosearch_ui.c`, `patcher/groups/__init__.py`)

대상은 SAN14CE_KO.exe 1.0.1(PE timestamp 0x6A983C25)이고, 주소는 모두 이미지 기준 RVA다. 전체 구조와 공통 게임 구조(상태 스택, UI 기본)는 [00-overview.md](00-overview.md).

## 하는 일
- 원본: 탐색은 플레이어가 탐색 → 자동탐색 → 결정을 직접 눌러야 한다. 패치: 자동탐색 설정 화면(2단계)의 조건 3행 아래에 같은 모양의 4번째 행 "자동진행 [켬][끔]"이 생기고, 켬이면 턴(페이즈) 종료 확정 직후 남은 명령서로 2단계 조건에 맞는 무장들에게 탐색을 자동 실행한다.
- 조건은 2단계에서 마지막으로 "결정"한 실행무장·귀환·중시 값(게임이 원래 세이브에 저장)을 그대로 쓴다. 켬/끔도 "결정"에서만 확정되고 "뒤로"면 버린다.
- 켬/끔은 세이브별 저장. 새 게임·패치 전 세이브는 끔. 진행 중 세이브에 바로 적용된다(새 게임 불필요).
- 켬/끔 버튼에 마우스를 올리면 1~3행처럼 하단 안내줄에 설명이 나온다.

## 구현 방식
- 패처는 데이터 파일 없이 `san14patch.ini [groups] auto_search=1`만 쓴다(`_DllOnly`). DLL은 `g_cfg.auto_search`일 때 `feat_autosearch_init` → 턴 종료 지점 교체 → `feat_autosearch_ui_init`(UI 연결 실패해도 턴 종료 훅은 남고, 저장된 켬/끔 값대로 동작).
- 턴 종료: 0x44D041 `call 0x451100`(앞 `xor ecx, ecx`)을 감싼다. 턴 종료 버튼 확정 직후·실제 턴 진행 직전이라 남은 명령서만 쓴다. `flag == 0`, 켬(월드 +0x17AC 바이트 0 == 1), 상태 스택 맨 위가 CUserStrategyState(전략 맵 명령 대기)이고 전환 중이 아닐 때만 실행한 뒤 원래 0x451100으로 넘긴다. 예외는 SEH로 잡아 로그만 남기고 그 턴은 건너뛴다.
- 실행(`run_auto_search`)은 게임 "결정"(0x732290) 순서를 재현한다.
  1. 군단 = 0x32E8D0(월드)(플레이어 직할 군단), 0x32F500 유효·0x233960 플레이어 조작 확인. 명령서 `군단+0x14`(바이트) ≥ 비용 `[0x1A4856C]`.
  2. 0x500 B 가짜 상태: +0x470 군단, +0x478 = 빈 `std::map<CCityData*, int>`(16 B) n개(n = 0x22A9D0(0x40190(군단)), 1~0x40). 0x713E60은 상태의 이 두 칸만 읽고 맵은 필요할 때 채운다.
  3. 무장별 목표 도시 표 `[0x277E278]`(0xBB88 B)이 NULL이면(2단계 화면 밖) 게임 할당자 0x3F6E80으로 만들고 0으로 채운 뒤 끝나면 0x3F6E90으로 해제.
  4. 월드 조건을 화면 라디오 번호로 바꿔(0x724B80과 같은 변환) `0x713E60(상태, ptr_list, 실행무장, 귀환, 중시)` → 화면과 같은 정렬의 후보 목록.
  5. 명령서/비용 개수까지 상위 후보마다 `area = 0x6DCE80(군단, 무장, [0x277E278][무장 id])`, `0x1F2B80({area, 무장}, 0x233960(군단))`. 명령서가 비용 미만이 되면 중단.
  6. 화면 닫기(0x720730)처럼 후보 무장의 +0x15E 비트 0x40과 +0x1CC를 지우고 목록·맵·상태를 정리한다.
- 켬/끔 UI: 2단계 vtable 슬롯 1(열기, 한 번만 불림)에서 4번째 행을 만들고, 슬롯 5(결정)에서 라디오 컨트롤러 +0x18을 저장, 슬롯 2(닫기)에서 정리, 슬롯 0(소멸자)에서는 포인터만 잊는다. 행 추가에 쓰는 레이아웃·라디오 컨트롤러·안내줄·애니메이션 그룹 함수는 [00-overview.md](00-overview.md) "UI 기본". 이 기능의 값:
  - 본 레이아웃(상태 +0x488): 노드 42·43·51(구분선·명령서·실행 무장 수)의 y −97, 노드 1·5(window·패널 배경) 높이 +97.
  - 복제 레이아웃 `"06_07_01_jinji_search_cn"`: 노드 1·6·21·42·43·51 숨김, 3행 묶음 노드 33 y −97. 라디오 `0x92E430(res, 0x24, 0x12, 1, 1, 0)`·`(res, 0x27, 0x14, 1, 1, 0)`, 라벨 노드 0x23 "자동진행"(0x9310A0, 0xD), 버튼 글자 "켬"/"끔"(0x85C9C0). 컨트롤러 인덱스 0 = 켬, 1 = 끔.
  - 안내줄: 푸터(상태 +0x4A8) → `0x84EC80([푸터+0x180])` → `0x89B1C0(관리자, 버튼, 문구, 0)`. 켬 "페이즈 종료시 위 조건에 맞춰 남아있는 명령서를 이용해 탐색을 자동으로 진행합니다.", 끔 "페이즈 종료시 탐색을 자동으로 진행하지 않습니다."
  - 복제 열기 후 `0x570440(상태, 1, 복제)`로 화면 애니메이션 그룹에 등록.
- 저장: 월드 `[root+0x871E8]` +0x17AC(4 B, 게임 미사용 칸)의 바이트 0(`world_extra()`, `WX_AUTO_ON`). 0 = 끔, 1 = 켬. 바이트 1·2는 그룹 1(숙련 배율, [01-expert.md](01-expert.md))이 쓴다. 원본 게임은 이 칸을 새 게임 때 0으로 채우고 직렬화만 하므로 원본으로 불러도 영향 없다.

## 새 버전에서 다시 맞추는 순서
1. RTTI로 CStrategyAutoSearchState·CUserStrategyState·CUILayout vtable을 얻고, 2단계 슬롯 0/1/2/5 원래 함수를 위 근거(레이아웃 이름 문자열, +0x17B0 쓰기, 정리 순서)로 확인한다.
2. "결정" 함수에서 0x713E60·0x6DCE80·0x1F2B80·0x233960 호출, 비용 전역, 군단 +0x14, `[0x277E278]` 읽기를 다시 얻는다. 0x713E60이 상태 +0x470/+0x478만 읽는지 확인한다.
3. 열기 함수에서 `[0x277E278]` 할당(크기 0xBB88), 레이아웃 로드·라디오·컨트롤러·안내줄 호출 묶음을 얻고, 실행 중 노드 이름(+0xB0)을 나열해 노드 ID(1·5·6·21·33·42·43·51, 라디오 0x24·0x27, 라벨 0x23)와 행 간격 97을 다시 맞춘다.
4. 문자열 "CGameState"를 쓰는 0x451100 상당 함수를 찾고, `xor ecx, ecx; call` 호출처(턴 종료 확정 문맥)를 턴 종료 지점으로 정한다.
5. 새 실행 파일을 디스어셈블해 +0x17AC가 여전히 새 게임 초기화·직렬화에서만 쓰이는지 확인한다. 바뀌었으면 다른 미사용 칸을 찾고 그룹 1과 같이 옮긴다.
6. 상태 스택 전역, ptr_list 노드 표, 맵 생성자·소멸자, 0x32E8D0·0x40190·0x22A9D0을 갱신한다(0x40190·0x22A9D0은 근거가 없어 새로 찾아야 한다).

## 검증
- 게임에서 확인: 2단계 화면에 4번째 행 표시, 버튼 안내줄, 다음 단계(무장선택)로 가면 행이 숨고 돌아오면 보임, 화면을 나가도 게임이 종료되지 않음.
- 게임에서 확인: 켬 + 결정 후 턴 종료 → 남은 명령서만큼 탐색 실행(명령서가 비용 단위로 줄고 탐색 무장 생김).
- 게임에서 확인: 세이브별 켬/끔 저장(저장 후 불러오면 그 값, 새 게임 끔).
- 확인 기록 없음: 귀환·중시 조건별 후보가 화면의 "결정" 결과와 같은지, 0x40190·0x22A9D0으로 만든 맵 개수가 화면의 X와 같은지.
- 실패는 `dll.log`의 "[자동 탐색] …"(문맥 불일치, 예외 RVA, 4번째 행 생성·정리 예외)로만 남는다(성공 줄은 남기지 않음).

## 함정·결정
- 화면 밖에서 0x713E60·"결정" 경로를 부르면 `[0x277E278]`이 NULL이라 C0000005 → 없으면 게임 할당자로 만들고 끝나면 해제.
- 일반 버튼은 "눌린 모양"을 유지할 수 없어 켬/끔은 1~3행과 같은 라디오 4번째 행으로 만든다.
- 켬/끔 설명은 말풍선이 아니라 1~3행과 같은 하단 안내줄(0x89B1C0)로 띄운다.
- 노드를 트리에 끼우는 대신 같은 레이아웃을 한 벌 더 불러와 3행 묶음만 남기는 방식을 쓴다.
- 복제 레이아웃을 소멸자에서 바로 지우면 화면을 나갈 때 0xC0000409 → 닫기 슬롯에서 게임과 같은 순서로 정리, 소멸자에서는 포인터만 잊음.
- 애니메이션 그룹(0x570440)에 등록하지 않으면 다음 단계에도 행이 남음.
- 슬롯 1은 열 때 한 번만 불리므로 거기서 선택값을 읽으면 저장되지 않는다. 클릭은 컨트롤러가 스스로 +0x18에 반영(0x4525E0)하므로 "결정" 슬롯 5에서 읽음.
- 켬/끔은 전역 설정 파일이 아니라 세이브별 월드 +0x17AC에 둔다. 0 = 끔이라 새 게임 훅이 필요 없음.
- 후보는 직접 거르지 않고 게임 0x713E60을 쓴다(화면과 같은 후보·정렬, "2단계 조건 그대로"라는 설계 결정). 실행도 "결정"의 순서(0x6DCE80 → 0x1F2B80)를 그대로 따른다.
- 0x44D041의 원래 바이트가 예상과 다르면 이 기능만 적용하지 않는다.

# 그룹 2. 개성 조정 (새 게임 필요) (`traits` / ini `trait_balance` / 소스 `src/dll/feat_jeodol.c`, `patcher/groups/traits.py`)

대상은 SAN14CE_KO.exe 1.0.1(PE timestamp 0x6A983C25)이고, 주소는 모두 이미지 기준 RVA다. 전체 구조와 공통 게임 구조는 [00-overview.md](00-overview.md), 데이터 파일 형식은 [data-formats.md](data-formats.md).

## 하는 일
- 데이터: 저돌(ID 1)에 효과2 "공군 효과치 1(5%)", 투장(ID 108)에 효과2 "공군 효과치 2(10%)"를 넣는다. 투장은 효과1과 조건 26(포위됨)을 공유해 포위됐을 때만 오른다. 저돌·투장·구심·악주 설명문도 고친다. **새 게임부터** 적용된다(세이브에 개성 사본이 있음).
- DLL: 원본은 저돌 효과(효과 ID 1: 적 접근 시 돌진, 명령설정 적접근시「무시」·자주퇴각「허가」 선택 불가)가 늘 적용된다. 구심(21)·악주(23) 대장 부대(자기 제외) 연계범위(3칸) 안의 비적대 부대는 대장의 저돌 효과가 0으로 판정된다. 무효인 동안 발동개성 표시를 끄고 적접근시를 「무시」로, 다시 발동하면 「공격」으로 바꾼다. 로직이라 **진행 중 세이브에도 즉시** 적용된다.
- 저돌의 다른 효과(새 공군 증가)는 무효 중에도 그대로다. 데이터·DLL 부분은 그룹 하나로 함께 켜고 끈다. 시험용으로 `apply --data-only 2`가 있다.

## 구현 방식
데이터 부분(`traits.py`):
- 개성 정의는 두 곳에 있다. fixdata(`0010_*/fixdataexce.s14`)는 설명문·효과, 시나리오 사본(`scedaexce*.s14`)은 새 게임이 조건·효과를 실제로 읽는 곳이다. 둘 다 고친다.
- 표 찾기(`find_table`): 해제 데이터에서 청크 헤더 `(22, 356)`(u32 2개)를 검색하고, 표 끝(시작 + 356 × 크기) 다음 u32가 청크 23인 크기를 고른다. 정확히 한 곳이어야 한다. 크기 후보는 fixdata 170(KO·SC·TC)·150(JP), 시나리오 60.
- 필드: fixdata는 레코드 끝 기준(조건 끝−22, 효과1 끝−18, 효과2 끝−15, 설명 44 ~ 끝−24), 시나리오는 고정(조건 44, 효과1 54, 효과2 57). 효과 칸 = `<Bh`(효과 ID u8 + 효과치 s16).
- 쓰기 전에 개성 1·108의 조건1·2, 효과1·효과치1, 효과2(0, 0)를 검사하고 다르면 거부한다. 설명문은 언어별 원문이 `DESCS`와 같아야 고치고, UTF-16LE로 덮은 뒤 NUL로 채운다. 칸 길이(51자/JP 41자)를 넘으면 거부.
- 저장(`S14.to_bytes`): 길이가 같으므로 `lwc.repatch`(원본 토큰 유지)로 다시 쓴다. fixdata는 원본 헤더 서명이 맞을 때만 고치고(아니면 거부) 463의 서명을 다시 계산한다. 시나리오는 서명 없음. DLC 시나리오는 XOR seed를 찾아 풀고 같은 seed로 다시 싼다. 형식(LWC, fixdata 헤더 서명, DLC XOR)은 [data-formats.md](data-formats.md).
- 대상: `0010_{JP,KO,SC,TC}/fixdataexce.s14` 4개 + `0010_*/scedaexce*.s14` 50개씩 + `DLC/0010_*/scedaexce*.s14`. 1.0.1 기준 216개(fixdata 4 + 시나리오 212). EN은 `DESCS`에 없어 빠진다.
- 해시 목록에 없는 시나리오(DLC 11·19·29 등, 다른 도구로 저장한 파일)는 `verify_unknown`으로 내용 확인: 경로가 `(DLC/)0010_xx/scedaexceNN.s14`, DLC면 번호가 `DLC_SCENARIOS`에 있음 → 풀림 → 개성 표(60 B) 찾음 → DLC면 seed = DLC_ID + 번호 → 개성 1·108 값이 원본. 통과하면 원본으로 백업·적용, 실패하면 그 파일만 건너뛰고 `[진단]` 로그와 GUI 완료 창에 남긴다. fixdata는 계속 쓰기 전에 거부(`core.UnknownFile`).

DLL 부분(`feat_jeodol.c`):
- 게임은 저돌 효과를 모두 "무장 효과 값 합" 0x2B2DA0(무장, 1)로 판정한다. 그 호출 4곳을 감싸, 원래 값이 0이 아니고 그 무장이 대장인 부대가 무효 범위 안이면 0을 돌려준다. 효과 ID로 판정하므로 개성이 아니라 효과 단위로 무효다.
- 무효 범위(`unit_nullified`): 대상 부대가 0x233440 ≠ 0이면 제외. 부대 표 1..500 중 자기 아닌 활성 부대 h가 칸 거리 0x2AA850 ≤ `[0x1A48FD8]`, h 대장의 개성 9칸(0x2305D0)에 21·23, 0x2CA280(세력, 세력) 비적대면 무효. 게임 범위 개성 처리 0x27E1D0과 같은 재료이고, 반경 안 목록 함수 0x2A7490 대신 대장 칸 사이 거리를 쓴다.
- 표시: 발동 판정 0x89E650(부대, 칸) 호출 5곳을 감싸, 그 칸 개성 객체의 효과1·효과2(+0xB6/+0xBA) 중 1이 있고 부대가 무효 범위면 0을 돌려준다.
- CArmyInfoLayout 매 프레임 함수(vtable 슬롯 2)를 감싸, 저돌 효과 부대만 점 갱신 0x1AC030(+0x260, 부대)을 직접 부르고 부대 +0x40(적접근시)을 무효 1 / 재발동 2로 바꾼다. 부대별 직전 상태는 512칸 표(부대 포인터, 대장 id)로 기억하고, 처음 보면 "발동"으로 본다.
- 적용 단위: 4곳 중 하나라도 `mov edx, 1` 확인이나 중계기 생성이 실패하면 기능 전체를 적용하지 않는다. 표시 5곳 실패는 본 기능을 유지하고, vtable 실패는 로그만 남긴다.

## 새 버전에서 다시 맞추는 순서
1. 데이터: `find_table`이 4개 언어 fixdata와 시나리오에서 한 곳씩 찾는지 본다. 레코드 크기가 바뀌면 `FIX_STRIDES`·`SCEN_STRIDE`·`Layout`을 새 레코드 배치(조건·효과·설명 칸 위치)와 대조해 고친다.
2. 개성 1·108의 원래 조건·효과 값과 4개 언어 설명문 원문이 그대로인지 확인하고, 바뀌었으면 `EFFECTS`·`DESCS`를 고친다. fixdata 원본에서 `signature_ok`가 참인지 본다(거짓이면 서명 방식이 바뀐 것, [data-formats.md](data-formats.md)).
3. DLC 표를 exe에서 다시 구해 `DLC_SCENARIOS`를 고치고, 새 원본 파일의 해시로 `known_files.json`을 다시 만든다.
4. DLL: 0x2B2DA0(9칸 개성마다 0x22C630 합)을 찾고, 그 호출 중 앞에 `mov edx, 1`이 있는 4곳으로 `SITES`·`edx_back`을 갱신한다(AI, 0xA1D00 출진 강제, 0x2EE010 선택지, 명령설정 화면).
5. 조건 처리기 표 → 조건 9 처리기 → 범위 처리 0x27E1D0에서 0x2A7490·0x233440·0x22CC40·0x2CA280과 연계범위 전역을 다시 찾는다. 0x2AA850·0x2305D0·0x32F500도 갱신.
6. 실행 중 메모리(ReadProcessMemory)로 무장 +0x10/+0x118, 부대 +0x10/+0x12/+0x2A/+0x40, 개성 객체 +0xB6/+0xBA, 루트 표 오프셋을 확인한다.
7. 표시: RTTI CInfoDetailArmyUnitDefault 슬롯 49에서 0x89E650을 찾고 그 호출 5곳을 `ACTIVE_SITES`로, RTTI CArmyInfoLayout vtable 슬롯 2와 그 안의 0x1AC030(+0x248, +0x260)을 갱신한다.
8. 빌드 판별(PE timestamp·SizeOfImage)은 공통 절차로 갱신한다([00-overview.md](00-overview.md) 업데이트 절차).

## 검증
- 데이터(확인): 단위 테스트 `tests/test_traits.py`(시나리오는 효과2 4바이트만 바뀜, DLC XOR 유지, fixdata 효과·설명문·서명, 복원·그룹 전환, 모르는 DLC는 내용 확인 후 적용·값 다르면 건너뜀). 원본 사본 216개 적용 → status 일치 → 복원 후 원본과 바이트 동일. KO 게임 로드, 투장 공군은 포위 시만 발동, 새 투장 설명문 표시.
- DLL(게임에서 확인): 저돌 대장 부대가 구심·악주 대장 부대 3칸 안이면 적접근시「무시」·자주퇴각「허가」 선택 가능, 밖이면 잠김, 공군 증가 유지. 무효/재발동에 따라 적접근시 무시 ↔ 공격 전환, 상세 창 마커 꺼짐, 부대 마크 옆 점 변화.
- 미확인: 돌진 AI 변화, JP/SC/TC 실행 파일 게임 확인, 설명문 줄바꿈·잘림, DLC 시나리오 게임 로드, 범위 판정이 게임 범위 개성과 정확히 같은지(칸 거리 vs 0x2A7490 목록, 추정).

## 함정·결정
- 무효 단위는 개성이 아니라 효과 ID 1이다. 지금 데이터에서 효과 1은 저돌뿐이지만 나중에 다른 개성에 넣어도 함께 무효다.
- 연계범위 상수를 바꾸지 않는다. 연계와 다른 범위 개성까지 바뀐다.
- 투장 효과2가 조건 26을 공유해 포위 시만 발동한다. 조건을 0으로 바꾸지 않고 설명문을 맞췄다(설계 결정).
- 탈토는 효과 칸 2개가 모두 쓰여 있어 고치지 않는다.
- 진행 중 세이브에는 데이터 부분이 반영되지 않는다(세이브의 개성 사본). 메모리 개성 표를 고치는 방법은 쓰지 않는다.
- JP fixdata 레코드는 150 B다. 170으로 가정하면 표 판별이 실패한다.
- 부대 마크 점: 게임이 저돌을 늘 발동으로 봐 점 갱신 계기가 없으므로, 상세 창만 고치면 점은 꺼진 채 남는다. 그래서 매 프레임 0x1AC030을 직접 부른다(바뀐 칸만 고치므로 반복해도 같음).
- 자주퇴각의 부대 내 위치는 찾지 않았다. 출진 후에는 적접근시(+0x40)만 바꾼다.
- 시나리오 파일은 해시만으로 판별하지 않는다. 해시 목록에 없는 DLC 시나리오(11·19·29 등)도 `verify_unknown` 내용 확인으로 적용하고, 실패한 시나리오는 건너뛴다(그 시나리오 새 게임에서 저돌·투장 변화만 빠짐).

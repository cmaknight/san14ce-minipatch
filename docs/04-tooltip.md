# 그룹 4. 개성·전법 툴팁 개선 (`tooltip` / ini `trait_tooltip` / 소스 `src/dll/feat_tooltip.c`, `patcher/groups/__init__.py`)

대상은 SAN14CE_KO.exe 1.0.1(PE 타임스탬프 0x6A983C25)이고 주소는 모두 RVA다. 전체 구조와 공통 게임 구조는 [00-overview.md](00-overview.md).

## 하는 일
- 원본: 개성·전법 설명 말풍선은 무장 상세 등 일부 화면에만 있고, 정보 > 무장 목록과 각 기능의 무장 선택 목록에서는 개성·전법 칸에 마우스를 올려도 아무것도 안 나온다. 패치: 그 목록의 개성 칸에는 개성 설명 말풍선, 전법 칸에는 무장 상세와 같은 전법 말풍선(머리줄 의존능력·대거점·간격 포함)이 뜬다.
- 전법 말풍선의 효과 줄에 효과량·범위를 덧붙인다: "피해 (15)", "아군 공군상승 (3, 반경 1)", "이름 (반경 N)". 효과량 0·범위 0이면 원래 글자. 같은 말풍선 클래스라 무장 상세 화면의 전법 말풍선도 같이 바뀐다.
- 즉시 적용(새 게임 불필요). 무장 상세처럼 원래 툴팁이 있는 화면의 동작은 건드리지 않는다.

## 구현 방식
- 패처는 `san14patch.ini [groups] trait_tooltip=1`만 쓴다(`_DllOnly`). DLL은 `g_cfg.trait_tooltip`일 때 `feat_tooltip_init`.
- 대상 목록 CCmnInfoList<iterator_type<CPersonData*>>(vtable 0x13ACF30)의 매 프레임 갱신 슬롯 1을 감싼다. 원래 함수 뒤 마우스 아래 대상을 판정해 말풍선을 띄우거나 숨기고, 닫기 슬롯 5·비활성 슬롯 8에서 숨긴다. 판정(`hovered_obj`):
  1. UI 매니저 0x1B62110 +0x170(마우스 아래 위젯, +0x18C ≠ 0이면 없음)이 이 목록 현재 탭(+0x208) 본문(`[+0x130][탭]`)의 행(행 +0x48 == 본문)이고, 마우스(입력 0x11290 +0x34/+0x38)가 본문·행 안인지 확인.
  2. 행 → 무장: `0xAE0370([[[본문+0x138]+0x20]+0x20], 행 +0x80)` = 데이터 인덱스 → `[본문+0x198][i]`(개수 본문 +0x1A0).
  3. 열: 헤더 버튼 벡터(+0x210..+0x218, [0]은 체크 칸)를 x만으로 히트테스트 → 버튼 +0x80 = 보이는 열 번호(벡터 위치 −1과 같아야 함) → 탭 정의(+0x150, 24 B, +0 열 ID 배열) → 열 정의(+0x158 표, 0x60 B: +0x18 값 함수, +0x5C 사용).
  4. 값 함수(무장)가 돌려준 글자 포인터가 개성 객체(`root+0x7DD18+id*8`, id 1~0x162. 게임 표는 0~0x163, [00-overview.md](00-overview.md) 공통 게임 구조) +0x10이면 개성, 전법 객체(`root+0x774D0+id*8`, id 0~0xC8) +0x10이면 전법. 열 ID를 하드코딩하지 않으므로 이름 포인터를 돌려주는 열이면 어느 탭이든 동작한다.
- 개성: 공용 CSimpleBalloonLayout에 `0x3594B0(개성 객체)` 설명을 넣는다(`tooltip_show(개성 객체, 설명)`).
- 전법: 별도 CTacticsBalloonFullLayout(0x1A8 B)을 한 번 만들고(생성자 0x89A300 → 슬롯 49 → 슬롯 14(6) → +0x40 |= 8 → 슬롯 25(0) → 슬롯 7) `0x8A1330(말풍선, 전법)`으로 전법을 바꿀 때만 지정, 위치 0x8A5D60(마우스 +20, +20), 보이기 슬롯 25. 개성 말풍선과 한쪽을 띄우면 다른 쪽을 숨긴다.
- 효과 줄: 0x8A2B50(전법 말풍선 다시 그리기) 안의 `call 0x930D20`(0x8A2E18, `(말풍선+0x130, 자식 ID 16/18, 효과 이름, 1)`)을 감싼다. 전법 = `[말풍선+0x178]`, i = 0(ID 16)/1(ID 18). 효과량 = `0x341000(전법, i)`. 범위 = 전법 +0x70..+0x78 덮어쓰기 목록이 10칸(0x28 B)이면 vfunc 슬롯 9(전법, 목록[i ? 0x10 : 0xC], 1, 0x22E0A0(전법)), 아니면 전법 +0x64+i. 글자는 정적 버퍼(효과별 128자)에 만들어 넘긴다. 예외면 원래 글자. 이 지점 교체가 실패해도 목록 툴팁은 유지된다.
- **공용 부분(다른 기능용, `src/dll/common.h` 선언)**: `tooltip_show(key, 글자)` / `tooltip_hide(key)`(CSimpleBalloonLayout 하나를 공유, key = 지금 내용의 주인, `tooltip_show(key, NULL)`은 표시 중인 key의 위치만 갱신), `ui_hovered()`(UI 매니저 +0x170), `ui_mouse_in(위젯)`(입력 좌표 + 부모 체인 히트테스트, 보이는 위젯만). 훅 없이 동작하고 말풍선은 처음 쓸 때 만든다(`trait_tooltip`이 꺼져도 호출 가능).

## 새 버전에서 다시 맞추는 순서
1. RTTI로 CCmnInfoList<iterator_type<CPersonData*>> vtable을 얻고 슬롯 1/5/8 원래 값(기본 갱신·닫기·비활성)을 확인한다.
2. 정보 > 무장 목록을 열고 개성 탭(탭 6)·전법 칸에 마우스를 올린 채 실행 중 메모리로 목록·본문·행 오프셋, 열 정의 표, 헤더 버튼 +0x80을 다시 맞춘다. 0xAE0370은 본문 스크롤 객체를 받는 함수를 새로 찾는다.
3. UI 매니저(+0x170/+0x18C)와 입력 0x11290(+0x34/+0x38)을 0x10FC0·0x86B3B0 관계로 확인한다.
4. 개성·전법 객체 표(root +0x7DD18/+0x774D0)와 이름 +0x10, 값 함수가 여전히 이름 버퍼 포인터를 돌려주는지(포인터 비교 식별의 전제) 확인한다. 0x3594B0은 무장 상세 개성 툴팁에서 찾는다.
5. RTTI CSimpleBalloonLayout·CTacticsBalloonFullLayout과 0x88ABC0 상당 생성 순서로 생성자·슬롯 49·0x8A1330을 얻고, 0x8A1330 → 다시 그리기 함수 안에서 자식 ID 16/18에 0x30CE40(효과 ID) 결과를 넣는 `call 0x930D20`을 새 효과 줄 지점으로 정한다.
6. 전법 목록 열 정의 표에서 열 5/9(효과량 0x341000), 7/11(범위 값 함수)를 보고 범위 계산(전법 +0x64/+0x65, 덮어쓰기 목록, vfunc 슬롯 9, 0x22E0A0)을 다시 맞춘다.

## 검증
- 게임에서 확인: 정보 > 무장 목록 개성 칸에 마우스를 올리면 개성 설명 말풍선이 뜬다.
- 게임에서 확인: 전법 칸에 무장 상세와 같은 전법 말풍선(머리줄 포함)이 뜬다.
- 게임에서 확인: 전법 말풍선 효과 줄 "(효과량, 반경 N)" 표시, 목록·무장 상세 모두.
- 미확인: 도시·부대 등 다른 목록 클래스(다른 템플릿 인스턴스, vtable 다름)는 대상이 아니다. 개성 슬롯 6~9를 보이는 열이 있으면 같은 방식으로 잡힐 것으로 본다(정황).

## 함정·결정
- 무장 상세(CInfoDetailPersonDlg) 개성 칸처럼 원래 툴팁이 있는 화면은 건드리지 않는다.
- 내용 식별은 열 ID가 아니라 값 함수가 돌려준 글자 포인터와 개성·전법 이름 버퍼(+0x10) 비교다. 게임이 이름을 복사해 넘기게 바뀌면 깨진다.
- 헤더 버튼 +0x80이 벡터 위치와 어긋나거나 탭 열 배열에 −1이 끼면 판정을 포기한다(잘못된 열 대신 표시 안 함).
- 전법 칸은 무장 상세와 같은 전법 말풍선을 쓴다. 전법 목록 열 정의 표(0x1A3A6A0)의 머리글·값 함수로 "계통: …" 줄을 조립하는 방식은 수치가 과하고 읽기 어려워 쓰지 않는다.
- CTacticsBalloonSimpleLayout(0x1477A38, 지정 0x8A1340)은 머리줄이 없어 Full을 쓴다.
- 개성 말풍선(공용)과 전법 말풍선을 따로 두고 한쪽을 띄우면 다른 쪽을 숨긴다. 목록이 공용 말풍선을 쓰는 중일 때만(`g_list_owns`) 목록이 숨긴다.
- 효과 줄 훅은 말풍선 클래스 단위라 무장 상세에도 적용된다(의도).

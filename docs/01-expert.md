# 그룹 1. 숙련 모드 보강 (`expert` / ini `expert_scaling` / 소스 `src/dll/feat_expert.c`, `patcher/groups/__init__.py`(`_DllOnly`, 데이터 파일 없음))

대상은 SAN14CE_KO.exe 1.0.1(PE timestamp 0x6A983C25)이고, 주소는 모두 이미지 기준 RVA다. 전체 구조와 공통 게임 구조는 [00-overview.md](00-overview.md).

## 하는 일
- 숙련 상세 설정 탭 2의 "타세력 인접지역효과" 아래에 "자신세력 기본 부대능력"·"타세력 기본 부대능력" 슬라이더 2행(50~200%, 기본 100)을 넣는다. 숙련 모드에서 부대 전투력(공군·공성·방어)에 배율로 곱한다. 파성·기동·전법 피해는 그대로다.
- 배율 값은 세이브별로 저장된다(새 게임·패치 전 세이브는 100%). 설정 슬롯 저장·불러오기·초기화, 시작 전 설정 확인 화면에도 두 값이 나온다.
- 자신/타세력 인접지역효과(#12·#13) 슬라이더 최대 200 → 2000. 무장경험획득(#24) 최소 100 → 0, 안내줄을 0 설명이 든 3줄 문구로 바꾼다.
- 적용 시점: 배율·범위는 새 게임 설정 화면에서 정한다. 이미 저장된 세이브의 배율 값은 그 세이브를 불러오면 바로 적용된다.

## 구현 방식
- 화면 행: 숙련 상세 설정은 "행 위젯 9개 + 항목 배열" 가상 목록이다. 목록(CSetUpScenarioSeniorList)의 행 개수 설정 vfunc(슬롯 53)를 감싸, 새 배열(+0x158)에서 칸 5 항목을 찾고 그 뒤에 칸 61·62 항목(칸 5 항목 0x60 B 복사, 칸 번호·값·이름만 바꿈)을 끼운 n+2 배열로 바꾼다. 그리기·새로고침은 게임이 한다.
- 값 읽기 0x3EA400·쓰기 0x3EFCE0은 `cmp edx, 0x3c; ja`로 칸 > 0x3C를 빠져나간다. 그 `ja rel32`(6 B)의 대상을 중계기로 돌려 칸 61·62만 DLL 값(`g_pend[2]`)으로 처리한다. 호출처 수백 곳을 감싸지 않는다.
- 범위 표: 0x14005C0(칸당 int 7개 = 최소, 최대, 난이도별 기본 5, 61칸, 0x1C B/칸)은 뒤에 다른 데이터가 있어 늘릴 수 없다. `near_alloc`으로 이미지 ±2 GB 안에 63칸 사본을 만들고 표를 가리키는 `lea r, [rip+d]` 5곳의 d를 바꾼다. 같은 사본에서 칸 61·62 = {50, 200, 100×5}, 칸 4·5 최대 200→2000(원래 200일 때만), 칸 24 최소 100→0(원래 100일 때만).
- 안내줄: 행 설정 0x640F20 호출을 감싸, 원래 처리 뒤 행 위젯 5개에 0x89B1C0(관리자, 위젯, 문구, 0)으로 문구를 등록한다. 칸 61·62는 배율 설명, 칸 24는 항목 +0xC가 0일 때만 3줄 문구.
- 세이브 저장: 월드 `[ROOT+0x871E8]` +0x17AC(4 B, 게임이 새 게임 때 0으로 채우고 직렬화만 함)를 바이트로 나눠 1번 = 자신 %, 2번 = 타세력 %(0이면 100). 0번은 그룹 3 자동진행([03-autosearch.md](03-autosearch.md)). 슬라이더를 바꿀 때 현재 월드에, 월드 초기화 0x325B80의 두 호출처 직후마다 쓴다. 값은 되돌리지 않는다.
- 적용: 전투력 0x2A8D40의 모든 호출(call 22 + 꼬리 jmp 1)을 감싸, 숙련 모드이고 부대가 유효하고 배율 바이트가 0이 아닐 때 결과 × %/100. 공군 0x2B21A0·공성 0x2B2440·방어 0x2A9E50이 이 값을 받고, 파성 0x2AA2E0·기동 0x2B0290·전법 피해 0x176B80은 받지 않는다. 자신 = 플레이어 세력(0x2337B0).
- 설정 슬롯: 게임 칸은 int 6개(0 현재, 1~5 슬롯)이고 설정 파일(configS)에 있어 칸을 늘릴 수 없다. 0x3EF930(복사)·0x3EEFE0(초기화) 호출처를 감싸 우리 두 값을 `%LOCALAPPDATA%\san14patch\settings.ini` [expert] `slotN_self`/`slotN_other`에 저장·복원한다(없거나 50~200 밖이면 100).
- 확인 화면: 0x5D1310이 항목을 넣는 0x58820 호출을 감싸 이름 0x888(#13) 항목 뒤에 숫자 항목 둘을 넣고, 이름 조회 0x30CF80 호출 한 곳만 감싸 가짜 메시지 ID 0x7E0001/2에 우리 문구를 돌려준다.
- 모든 지점은 원래 값(호출 대상·분기 대상·lea 대상·vtable 값) 확인 뒤 일괄 적용. 묶음(전투력 / 설정 행 / 새 게임 기록 / 슬롯·확인 화면) 하나라도 어긋나면 그 뒤 묶음은 걸지 않고 `[숙련] 기본 부대능력 일부 실패` 로그.

## 새 버전에서 다시 맞추는 순서
1. RTTI `CSetUpScenarioSenior*`로 List vtable을 얻고, 탭 채우기 함수(0x466220 상당)가 부르는 슬롯 번호·원래 함수를 확인한다(필요하면 슬롯을 감싸 호출 스택을 로그로 남겨 본다). 항목 0x60 B 배치와 목록 +0x158/+0x160은 실행 중 메모리로 다시 본다.
2. `cmp edx, 0x3c; ja`로 시작하는 점프 표 함수 둘(읽기·쓰기)을 찾아 `ja`의 위치·대상을 갱신한다. 칸 수(0x3C)가 바뀌면 IDX_SELF/IDX_OTHER(61·62)와 범위 표 칸 수(RANGE_N)도 같이 바꾼다. 칸 4·5·24의 의미는 읽기 함수 점프 표(설정 번호 대응)와 메시지 표 .rdata 0x13FFA78로 확인한다.
3. 범위 표: `imul r, r, 0x1c` 뒤 `lea r, [rip+…]`로 표 주소를 얻고, 새 실행 파일 전체를 디스어셈블해 그 표를 가리키는 lea를 모두 찾는다(지금 5곳). 칸 4·5 최대 200, 칸 24 최소 100인지 본다(아니면 소스는 그대로 두고 로그만 남김).
4. 행 설정 함수(범위 표 lea 하나와 0x85B1B0/0x85B1A0 호출을 품은 것)와 그 호출처, 안내줄 등록 0x89B1C0, 행 위젯 안 5개 위젯 오프셋을 다시 맞춘다.
5. 월드 +0x17AC: 직렬화 함수에서 그 칸이 여전히 저장되고 다른 읽기가 없는지 디스어셈블 결과에서 검색하고, 새 게임 초기화(그 칸을 0으로 채우는 함수)의 호출처를 모두 찾는다(지금 2곳).
6. 전투력: 0x3EA400을 칸 4·5로 부르는 0x2B07C0 → 그 호출자 중 0x340C00 계열에서 공군·공성·방어 함수에 결과를 넘기는 함수가 0x2A8D40이다. 그 함수의 E8·E9 호출처를 모두 다시 뽑아 POWER_CALLS·POWER_JMP를 갱신한다. 보조 함수(0x3E9C90, 0x3EB2F0, 0x22CC40, 0x2337B0, 0x32F500, ROOT+0xDF30)를 확인한다.
7. 슬롯: `cmp edx, 6; jae` 복사 함수(0x3EF930)와 초기화 함수(0x3EEFE0)의 설정 화면 안 호출처(화면 열기·불러오기/초기화 버튼·저장 2곳)를 찾는다. 확인 화면: 리소스 `02_03_03_setup_confirm_new2` → 항목 넣기 호출(이름 0x888 항목 근처)과 행 갱신의 메시지 이름 조회 호출을 갱신한다. 가짜 메시지 ID 0x7E0001/2가 실제로 쓰이지 않는지 본다.
8. 게임에서 "검증" 항목을 다시 확인한다.

## 검증
- 게임에서 확인: 탭 2에 두 행 표시, 새 게임 후 배율 적용, 슬롯 저장·불러오기·초기화에 두 값 포함, 설정 확인 화면 목록에 두 행, 안내줄 문구(% 포함) 표시.
- 확인 방법: 부대 정보의 공군 표시값에 전투력(인접효과·사기 포함)이 들어간다. 배율을 바꾼 새 게임에서 같은 부대 공군 표시값을 비교한다. 배율이 들어가지 않으면 월드 초기화 호출 시점을 로그로 확인한다.
- 게임에서 확인: 인접지역효과 슬라이더 2000까지 올라가고 적용 정상.
- 게임에서 확인: 무장경험획득 0까지 내려가고, 0이면 경험치 계산(0x2B9F4E)에 0이 쓰인다. 안내줄 3줄 표시(4줄이면 잘림).
- 미확인: 무장경험획득 0의 세부(숫자 입력, 슬롯·세이브에서 0 유지)는 따로 확인 기록이 없다. 전투력 UI 호출처(0x913E62 등)에서 표시가 배율과 맞는지 따로 확인하지 않았다. 칸 4·5를 200 넘게 했을 때 계수 상한·넘침 여부는 분석하지 않았다.

## 함정·결정
- 0x325B80은 한 판에 여러 번, 다른 경로(0x31AB46)로도 불린다. 한 호출처만 감싸거나 쓴 뒤 100으로 되돌리면 배율이 적용되지 않는다. 모든 호출처 뒤에 매번 쓰고 되돌리지 않는다. 슬라이더를 바꿀 때도 현재 월드에 바로 쓴다.
- 화면 값(`g_pend`)은 이 실행 동안 유지된다(게임 설정과 같음). 0은 "100%"로 읽어 새 게임·패치 전 세이브가 자동으로 기본값이 된다.
- 슬롯 53 시점의 +0x160은 이전 개수다. 새 개수 인자 n만 믿는다. 우리 항목이 이미 있으면 다시 넣지 않는다.
- 범위 표는 늘릴 수 없어 사본을 쓴다. 칸 4·5·24는 원래 값이 예상과 다르면 바꾸지 않고 로그만 남긴다.
- 값 읽기·쓰기는 호출처가 아니라 `ja` 하나씩만 돌린다. 분기 대상이 원래 함수 인자 레지스터를 그대로 받으므로 일반 C 함수로 받는다. `patch_branch`는 opcode(0F 87 / E9)를 실행 중 바이트에서 복사하고 rel32 대상만 확인한다.
- 설정 +0x6F8 둘째 벌(0x3EE6B0)은 "결정" 때 쓰는 직전 설정 사본이라 슬롯과 무관하다. 게임 슬롯은 configS 파일 안이라 칸을 늘릴 수 없어 우리 슬롯은 settings.ini에 둔다.
- 확인 화면 이름은 0x30CF80 자체가 아니라 0x5B86C6 호출 한 곳만 감싼다(다른 화면 영향 없음).
- 배율은 숙련 모드·부대(0x2A8D40은 거점에도 불림)·세력 1~0x33일 때만. 파성은 원본 인접효과도 들어가지 않아 제외, 전법 피해 0x176B80은 전투력을 쓰지 않아 제외(설계 결정).
- 칸 24 안내줄은 항목 +0xC ≠ 0(DLC 없음 문구)이면 덮지 않는다. 4줄은 잘려 100·500 설명을 한 줄로 묶었다.
- 원본으로 되돌려도 안전: +0x17AC 1·2번 바이트와 settings.ini는 원본이 읽지 않는다. 칸 24 = 0은 원본 로직에 클램프가 없어 패치를 꺼도 그 세이브는 0으로 동작한다(추정).

# 그룹 6. 로그 기능 보강 (`logs` / ini `log_plus` / 소스 `src/dll/feat_logs.c`, `src/dll/feat_logwnd.c`)

대상은 SAN14CE_KO.exe 1.0.1(PE 타임스탬프 0x6A983C25)이고 주소는 모두 RVA다. 전체 구조와 공통 게임 구조는 [00-overview.md](00-overview.md).

두 부분으로 나뉜다. 6-A는 로그 줄을 더 남기고(`feat_logs_init`), 6-B는 메인 로그 창을 바꾼다(`feat_logwnd_init`). 플래그 하나(`log_plus`)로 함께 켜진다. 패처 쪽 데이터 패치는 없다.

## 하는 일
- 사망: 원본은 군주·1품 관직·자세력·내 거점의 포로만 사망 로그를 남기고, 이벤트 사망은 자세력이어도 남기지 않는다 → 모든 세력 장수의 전사·처형·사망(수명 포함)과 이벤트 사망을 로그 줄로 남긴다. 원래 연출(대사·내레이션·부고 컷인)이 있던 경우는 그대로, 없던 경우는 로그 줄만.
- 포로: 이벤트로 포로가 될 때 플레이어가 잡았거나 잡혔으면 "{무장}, {세력}의 포로가 됨"(0x87E1)을 남긴다. 전투·일기토·함락은 원본대로.
- 내정 Lv: 플레이어 직할 군단 지역의 상업·농업·병영 Lv이 오르면 "{지역}의 상업Lv이 3으로 상승"을 남긴다. 하락·위임 군단·타 세력은 남기지 않는다.
- 로그 창: 위쪽 가장자리를 끌어 4~19줄로 조절, 확장 버튼은 최소(4)↔최대(19) 토글, 모든 높이에서 휠 스크롤, 스크롤바는 목록 높이에 맞춤. 높이는 `%LOCALAPPDATA%\san14patch\settings.ini` [log] rows에 전역 저장.
- 적용 시점: 즉시(진행 중 세이브 포함). 로그 줄은 게임 로그 기록기로 쓰므로 메인 로그·로그 목록에 함께 남는다.

## 6-A. 로그 추가 (`feat_logs.c`)

### 구현 방식
- 모든 로그 줄은 게임 로그 기록기 0x934400(this = CLogManager, `0x16EFC0()`)으로 쓴다. 인자 배치는 원본 호출을 본뜬다: 종류 0은 0x27A660(개발 최대치 로그), 종류 1은 포획 0x2E10B2. `0x934400(mgr, 종류, 군단, 위치, f5, [월드+0x450], 짧은문구, [0x1A47B98](L""), 무장id|0x1394, f10, f11, 0, 0)`.
- 기록기는 `[0x27842A0]+0x1B0 != 0`(이벤트 진행 중)이면 아무것도 쓰지 않는다. 우리가 부를 때만 그 칸을 0으로 내리고 끝나면 되돌린다(`call_log`).
- 문구는 문구 빌더 0x1A23440 vfunc+8(메시지 번호)로 펼친다. 빌더는 공용이라 우리가 쓰는 자리 0번(무장 +0x1CD8, 세력 +0x1D00, 장소 +0x1DC8)은 쓰고 나서 원래 값으로 되돌린다(`expand`).
- 사망: 사망 처리 0x295AA0의 관문 `test ebx, ebx; je 0x296535`(0x295C5F)에서 je 대상만 중계 스텁으로 바꾼다. 스텁은 원래 건너뛸 때(ebx==0)만 오고, 연출 생략 arg9 `[rbp+0x180]==0`·로그 arg8 `[rbp+0x178]!=0`·신분 `[r13+0xE6]`이 7(미등장)·8(미발견)이 아니면 표식 1바이트(스텁 +69)를 세우고 로그 구간 0x295FD6으로 간다. 아니면 원래 0x296535로. 레지스터는 원래 건너뛰는 경로와 같다(edi=0).
  - 표식이 서 있으면 부고 컷인 관계 판정 4곳이 0을 돌려 컷인 없이 0x296525로 빠진다. 원래 관문을 통과한 경우는 표식이 없어 원본과 같다. 표식은 함수 앞쪽 호출 0x295B03에서 지운다.
  - 로그 구간의 기록 호출 2곳은 `call_log`로 돌려 이벤트 사망(0x39EC7C·0x3AFC1A 경로)도 남긴다.
- 이벤트 포로: 0x3AB280 안의 포획 호출 0x3AB312(`0x2E0CF0`, a3=0·a4=0이라 원본은 로그 없음)를 감싼다. 호출 전에 원 세력(0x22CA00)과 군단(+0xE0)을 저장하고, 호출 뒤 신분(+0xE6)==6이고 잡은 세력(a5)이나 원 세력이 플레이어(0x2337B0)면 0x87E1을 종류 1로 쓴다. {P2}는 세력 자리 0번 = 잡은 세력 vfunc+0x60.
- 내정 Lv: 세터 `(지역, 값, flag)` 호출처 30곳(UI 0x621C70·0x621DA0 제외)을 감싼다. flag가 켜져 있으면 호출 전후 Lv(경계표 0x13A6D9C = {100, 300, 600, 1000})을 비교해 오르고 지역의 거점이 플레이어 직할 군단(`city vfunc+0x80 == 0x32E8D0([ROOT+0x871E8])`)이면 종류 0으로 쓴다. 지역 이름은 0x5F84 "{지역}의 모든 개발이 최대치가 됨"을 펼쳐 "의 모든 개발" 앞을 자른다. 조사는 Lv 3만 "으로".

#### 순 끝 상태 기계와 수명·병 사망 (배경)

패치는 여기에 걸지 않는다. 사망은 경로와 관계없이 사망 처리 0x295AA0을 지나므로 관문 하나로 모두 덮인다. 아래는 사망 로그를 게임에서 확인할 때 필요한 배경이다.

- 순 끝 처리는 단계 79개 상태 기계다. 디스패처 0x42DAB0(CGameState 0x44CABF에서 호출), 동작 표 0x1A61040[i], 조건 표 0x1A612C0[i].
- 단계 7 → 0x27BFA0 수명 사망(매월). 동작 표 칸 0x1A61078 = 0x427950이 부른다. 0x27C66D에서 0x295AA0(사인 0).
- 단계 8 → 0x27C6E0 병 사망. 0x27D30B에서 0x295AA0(사인 0). 대기 사망 목록을 순회하는 것으로 보인다(추정).
- 수명 사망 규칙(실행 중 값으로 확인):
  - 건너뜀: 경과 순 수(월드 +0x454, int로 읽음) ≤ 36, 수명 설정(0x3E9F10(0x3E9C90())) ≥ 2, 월드 +0x44 == 2.
  - 실효 졸년 = 졸년(무장 +0xAE) + 10(사인 +0xB0 == 1일 때) + 20(수명 설정 == 1일 때) + 아이템 보너스.
  - 확률(수명 설정 "사실"): d = 올해 − 실효 졸년. d ≤ 5면 d × 4%, 그보다 크면 d × 8%(최대 100%).
  - 관련 무장 필드: 플래그 +0x15E, 병 +0x161. 무장 +0x1E8은 낡은 값이라 쓰지 않는다([09-develop.md](09-develop.md)).
- 게임 확인 팁: 졸년이 이미 지난 무장이 있어도 게임 시작 뒤 36순(12개월) 동안은 수명 사망이 없다. 그 기간이 지난 뒤 사망·로그를 확인했다.

### 새 버전에서 다시 맞추는 순서
1. 로그 기록기: CLogManager 얻기 함수와 `[이벤트 포인터]+0x1B0` 검사, 링 버퍼 ROOT+0x79E90으로 0x934400을 찾는다. 빌더 0x1A23440의 자리 오프셋은 0x30DBB0·0x30D910·0x30D9D0이 쓰는 칸으로 확인한다.
2. 사망 처리: 메시지 0x2A2E~0x2A34를 쓰는 유일한 함수를 찾는다. 그 안의 `test ebx, ebx; je`(관문), 로그 구간 시작(0x295FD6 대응), 0x934400 호출 2곳, 컷인 큐의 관계 판정 4호출(뒤에 0x8C7A60), 앞쪽 첫 호출을 갱신한다.
3. 관문 스텁 바이트를 다시 확인한다: arg8·arg9의 `[rbp+…]` 변위, 사망 무장 레지스터(r13), 건너뜀 경로의 edi=0, 컷인 뒤 합류점(0x296525 대응).
4. 이벤트 포로: 신분 setter를 상수 6으로 부르는 함수(포획)를 찾고, 그 호출처 중 a3=0·a4=0인 이벤트 함수 쪽 호출을 갱신한다. 0x87E1 {P2}가 세력 자리 0번인지 다시 본다.
5. 내정: 0~1000으로 자르고 +0x3C/+0x3E/+0x40에 쓰는 세터 3개(같은 프롤로그)를 찾고, E8 호출처를 모두 모아 UI 쪽(flag=0) 2곳씩을 빼면 10곳씩이어야 한다.
6. 구조 오프셋(무장 +0xE0/+0xE6, 지역 +0x35/+0x3A, city vfunc+0x78/+0x80, 세력 vfunc+0x60, Lv 경계표)을 실행 중 메모리와 대조한다.

## 6-B. 로그 창 (`feat_logwnd.c`)

### 구현 방식
- 원본: 접힘(3줄)은 한 줄 위젯 4개뿐이고, 확장 버튼을 누르면 0x66B2C0이 CLogCtrlList(최대 19행)를 만들어 레이아웃 +0x1D8에 둔다. 이미 만든 목록의 크기만 바꾸는 setter는 없다.
- 목록을 항상 만들고(그래서 휠이 늘 동작) 행 수를 N으로 바꾼다. 0x66B2C0 안 상수 19 두 곳을 E9로 중계 스텁에 보내 N을 읽게 한다. N은 스텁 페이지 안 int 칸(`g_rows`)이고 시작 때 settings.ini [log] rows(기본 4, 4~19로 자름)로 채운다. 행 위치는 게임의 행 수별 노드 표 0x142D9A0(1~19행)을 그대로 쓴다.
- 목록 열기 호출 3곳을 감싸 연 뒤 맨 아래(최신)로 스크롤(0x875BC0(list, 1e9, 1)), 스크롤바 맞춤, 확장 버튼 아이콘(N==19면 접기 0x1CA, 아니면 펼치기 0x1C8, 버튼 vfunc+0x1F8(btn, 0xF, 아이콘))을 한다.
- 스크롤바(CCmnScrollbar, +0x1E0): 생성 때 보이는 분기(jbe)를 jmp로 바꿔 원본 표시를 막고, 열 때마다 목록 높이에 맞춰 vfunc+0x78로 옮기고 vfunc+0x158·+0x1A4로 길이를 바꾼 뒤 0x84CE60으로 화살표·트랙·손잡이를 다시 놓는다. 로그 수(+0x174) > N이고 길이 ≥ 화살표 높이×2+0x54(원래 최소, 0x851930)일 때만 보인다. 프레임마다 그 보임 상태를 다시 맞춘다.
- 프레임 갱신(CMainLogLayout vtable +0x10, 0x66F7C0)을 감싼다: 보이는데 목록이 없으면 연다. 목록 위 가장자리(위 1px ~ 안쪽 8px)를 왼쪽 버튼으로 누르면 끌기 시작, N = clamp((아래끝 − y + h/2) / h, 4, 19), 바뀌면 닫기 0x66F5D0 → 열기로 다시 만든다. 놓으면 settings.ini에 저장한다. 커서는 입력 객체 `0x11290()` +0x34/+0x38(캔버스 좌표), 목록 사각형은 0x86EB40과 같은 계산(부모 +8을 따라 +0x20/+0x24 합, 크기 +0x28/+0x2C), 행 높이는 0x92CF90(레이아웃+0x130, out, 2). 버튼은 `GetAsyncKeyState(VK_LBUTTON)`, 게임 창이 앞일 때만.
- ↕ 커서: 손잡이 위(누르지 않았거나 막 누른 순간)이거나 끄는 중이면 표식을 켠다. WM_SETCURSOR 처리(vtable 슬롯 0x13FE1F8, 0x574690)를 감싸 HTCLIENT이면 `SetCursor(IDC_SIZENS)`로 TRUE를 돌린다. 게임 커서 모드(설정 0x3E9C90 → 0x1EDA40 == 1)면 그동안 CSoftwareMouseCursorManager(0x86B400) +8 커서 그림을 vfunc+0xC8로 숨긴다.
- 확장 버튼(토글 람다 0x670170): N을 19↔4로 바꿔 저장하고, 목록이 있거나 +0x1E8이 켜져 있으면 닫은 뒤 원래 토글을 부른다. 원래 토글은 +0x1E8==0이면 연다.

### 새 버전에서 다시 맞추는 순서
1. RTTI로 CMainLogLayout vtable을 찾고 +0x10(프레임 갱신)을 갱신한다. CLogCtrlList vtable을 new하는 함수가 열기 0x66B2C0이다.
2. 열기 안에서 `lea ecx,[r12+0x13]`와 `cmp esi,0x13; mov eax,0x13; cmovg esi,eax`, 노드 표 `lea`, 스크롤바 표시 jbe를 찾아 두 스텁의 복귀 주소(각 명령 다음)와 jbe 위치를 갱신한다.
3. 열기의 E8 호출처 3곳(새 로그 갱신·프레임 갱신·토글)과 닫기 0x66F5D0을 확인한다.
4. RTTI `_Func_impl<lambda_b17226cf…>`(안에 `cmp dword [rcx+0x1E8],0`)의 +0x10을 갱신한다.
5. WM_SETCURSOR 처리 슬롯과 CSoftwareMouseCursorManager 얻기, 커서 모드 함수를 다시 찾는다(근거가 약하다).
6. 레이아웃·목록·스크롤바 필드와 스크롤바 vfunc 오프셋(+0x78·+0x158·+0x1A4, 버튼 +0x1F8)을 실행 중 메모리와 대조한다.

## 검증
- 게임에서 확인한 항목:
  - 사망 로그: 타 세력 일반 장수는 로그만, 원래 연출이 있던 경우는 유지, 이벤트 사망, 대규모 전투에서의 로그 양.
  - 이벤트 포로 로그.
  - 직할 군단 Lv 상승 로그, 위임 군단·하락은 남지 않음.
  - 로그 창: 4~19줄 끌기·토글·휠, 장면 전환 뒤 높이 유지, 지도 클릭과 겹치지 않음.
- 게임 확인으로 정한 것: 최소 4줄(3줄은 스크롤바 최소 길이 미만), ↕ 커서 추가(표시가 없으면 손잡이를 못 찾아 지도 스크롤과 겹침).
- dll.log에는 실패만 남는다: `[로그] 연결 실패: 사망 a, 이벤트 포로 b, 내정 Lv c`, `[로그 창] 연결 실패`, 원래 바이트 불일치.

## 함정·결정
- 사망 je 대상만 0x295FD6으로 바꾸면 플레이어와 관계 있는 AI 장수에게 부고 컷인이 뜬다. 그래서 표식 + 관계 판정 4곳 0 방식을 쓴다.
- 관문을 통째로 열면 대사·컷인·내레이션까지 다 나온다. 로그 구간만 탄다.
- 범위 필터 없음(모든 세력, 설계 결정). 미등장·미발견 신분만 제외. 대규모 전투에서 메인 로그가 밀릴 수 있다.
- 거점 함락 무장별 포로 줄(0x287166)은 만들지 않는다. 요약 0x2A8A와 겹친다.
- 내정은 세터 입구 훅이 아니라 호출처 30곳을 감싼다. DLL에 입구 훅 기반이 없다. Lv 하락은 남기지 않는다.
- 문구 빌더는 공용이라 자리 칸을 바꾸면 반드시 되돌린다.
- 로그 창 높이는 목록을 닫고 다시 만든다. 0x86C040 재호출은 +0x198 자식을 새로 할당해 메모리가 샌다. 픽셀 단위 높이는 행 단위 스크롤·클립 때문에 쓰지 않는다.
- 따로 손잡이 위젯(0x84ABA0)을 두지 않는다. 손잡이를 목록 안쪽 위 가장자리에 두면 목록 위젯이 클릭을 받아 지도로 가지 않는다.
- 스크롤바는 숨기지 않는다. 모든 높이에서 목록 높이에 맞춰 보인다(휠 추가가 스크롤바 제거를 뜻하지 않음).
- 0x66B2C0이 +0x1E8=1을 세우므로 원래 토글은 "열림"으로 보고 닫는다. 토글 훅이 먼저 닫아 원래 토글이 다시 열게 한다.
- settings.ini는 원본 복구가 지우지 않는다. 세이브와 무관한 전역 값이다.
